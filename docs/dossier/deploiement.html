01

Où et pourquoi Azure

Il me fallait un hébergeur qui garde les données en France, qui ne coûte presque rien sans visiteur et que je n'aie pas à administrer moi-même.

Des services managés, en France Central, couverts la première année par les offres gratuites d'Azure.

Azure était prévu dès le départ dans la CD reprise du triage médical. Mistral, lui, vend ses modèles par API mais n'héberge pas d'application. J'ai donc créé un compte Azure le 15/10/2026 : 200 $ de crédit de bienvenue sur 30 jours, des services gratuits pendant 12 mois (dont la base PostgreSQL) et des services toujours gratuits (Container Apps jusqu'à un certain volume).

Tout est rangé dans un seul groupe de ressources, sortiria-rg, en France Central : l'API, la collecte, la base et les journaux. Une seule commande suffirait à tout supprimer.

Les données en France

API, collecte de la nuit, base PostgreSQL et journaux sont en France Central. Mistral, le seul service externe, est hébergé en Europe.

L'interface en East US 2, par contrainte

Pour Static Web Apps, j'ai d'abord demandé Europe de l'Ouest : Azure a refusé (RequestDisallowedByAzure, la région n'accepte plus de nouveaux comptes), et France Central n'est pas proposée pour ce service. J'ai pris East US 2 : la région ne sert qu'à ranger la fiche du site, les pages sont distribuées par des serveurs du monde entier.

Un nom de domaine français

sortiria-montpellier.fr, acheté chez OVHcloud (un .fr pour un service local). Un enregistrement CNAME fait pointer www vers Static Web Apps, qui fournit le certificat HTTPS ; le CNAME était visible en moins de 5 minutes.

02

Les services

Sept morceaux, chacun avec un rôle unique. Le prix indiqué est le coût mensuel d'aujourd'hui.

9 $ / MOIS

Static Web Apps, offre Standard

Rôle : sert l'interface Angular (sortiria-web) et transmet à l'API toute adresse qui commence par /api (« backend lié »). Pourquoi Standard : l'offre gratuite ne sait pas relier une Container App. Une adresse inconnue renvoie index.html, sauf /api/* (staticwebapp.config.json).

0 $ · DANS L'OFFERT

Container Apps : l'API

Rôle : l'API FastAPI (sortiria-api). Réglages : 0,5 processeur, 1 Gio, de 0 à 1 réplique : elle se met en veille sans visiteur et se réveille en quelques secondes. Elle n'accepte que les appels passés par le site. Offert chaque mois : 180 000 s de processeur et 2 millions de requêtes.

0 $ · ≈ 10 % DE L'OFFERT

Container Apps Job : la collecte

Rôle : l'agent de la nuit (sortiria-collecte), même image que l'API, lancé par python agent. Réglages : cron 0 1 * * * (1 h UTC, 2 h à Paris en hiver), 1 processeur, 2 Gio, une heure au plus, un nouvel essai en cas d'échec.

0 $ LA 1RE ANNÉE

PostgreSQL Flexible Server

Rôle : la base unique, PostgreSQL 16 avec pgvector. Réglages : Burstable B1ms, 32 Go, sauvegarde 7 jours, ouverte aux seuls services Azure (et à mon poste). Gratuite 12 mois, puis environ 14 $ par mois en France Central, plus le stockage.

0 $ · 5 GO OFFERTS

Log Analytics

Rôle : les journaux de l'API et de la collecte, créés avec l'environnement Container Apps. C'est là que j'ai lu la panne du PDF de Sète agglopôle.

0 $ · PAQUET PUBLIC

GitHub Container Registry

Rôle : stocke l'image Docker de l'API, publiée par la CD, une image par commit (sha-<commit>). L'API et la collecte tournent sur la même image.

< 1 $ / MOIS

Domaine OVHcloud

Rôle : l'adresse publique www.sortiria-montpellier.fr, par un CNAME vers Static Web Apps. Un abonnement annuel de quelques euros.

Réglages : docs/deploiement.md et mon journal de déploiement (15-16/10/2026). Coûts : docs/couts.md, prix publics relevés le 16/10/2026, à vérifier sur les pages officielles. Mistral est facturé à part, à l'usage.

04

Comment : la chaîne CI/CD

Depuis le 16/10/2026, je ne tape plus aucune commande Azure pour déployer. Un push sur main lance la CI ; si elle est verte, la CD publie l'image puis met tout à jour.

OpenID Connect : Azure fait confiance à ce dépôt et à sa branche main, et à rien d'autre.

J'ai créé dans Azure une application sortiria-github-deploy, avec le rôle Contributeur sur le seul groupe sortiria-rg. À chaque exécution, GitHub présente un jeton signé qui dit « je suis ce dépôt, sur la branche main » ; Azure le compare à des identités fédérées déclarées à l'avance. Rien à renouveler, aucun mot de passe stocké.

GitHub ne garde que trois identifiants (application, annuaire, abonnement), qui ne sont pas des mots de passe, et une variable DEPLOY_ENABLED qui active ou coupe le déploiement.

Les vraies pannes, et ce que j'en ai fait

16/10/2026 • Connexion OIDC

« No matching federated identity record »

Au premier essai, la connexion a échoué (AADSTS700213). J'avais déclaré deux identités fédérées, une par écriture du nom du dépôt. Mais GitHub présente désormais un sujet qui contient les identifiants numériques du compte et du dépôt (ils ne changent pas si l'un des deux est renommé). J'ai lu le sujet exact dans le journal de l'étape « Azure login », ajouté une troisième identité fédérée avec ce sujet, puis relancé le job : vert.

15/10/2026 • Collecte sur Azure

Le PDF de Sète agglopôle bloqué

La première collecte sur Azure est sortie « PARTIEL » : 2 009 événements enregistrés, mais la source document en échec. Log Analytics disait « Le document téléchargé n'est pas un PDF », en 0,1 s, aux deux essais ; depuis mon poste, la même adresse renvoyait bien le PDF. Le site de l'agglopôle sert une page web aux centres de données (protection anti-robots probable).

15/10/2026 • Correction

SOURCES_DESACTIVEES=document

J'ai ajouté une variable qui coupe une source sur une machine : sur Azure, document n'est plus lancée, ses événements ne sont pas balayés et le mail l'indique. Je lis le programme depuis mon poste, vers la base de production (uv run python -m agent --source document) : 434 événements écrits, enrichis et vectorisés. Le diagnostic de l'agent range désormais cette panne en « accès bloqué », avec le bon conseil ; 4 tests ajoutés.

15/10/2026 • Mise en place

Les erreurs de la première journée

Une option de la ligne de commande Azure réservée aux grappes de serveurs, des services pas encore « enregistrés » sur un abonnement neuf, une syntaxe de règle de pare-feu changée, et la région Europe de l'Ouest fermée aux nouveaux comptes. Chacune est notée avec sa solution dans mon journal de déploiement.

LIMITE Le programme PDF dépend de mon poste de travail.

Il couvre septembre à décembre et ne change pas d'ici là : une lecture suffit. L'agent rappelle de chercher le programme suivant 21 jours avant la fin ; il faudra alors le relire depuis un poste, ou obtenir de l'agglopôle un accès autorisé.

Le même code tourne sur mon poste et sur Azure : seules les variables d'environnement changent. Leurs noms sont documentés dans .env.example ; leurs valeurs ne sont jamais dans git.

Liste complète dans .env.example (valeurs vides). Aucune valeur n'est reproduite sur ce site.

Sur mon poste

Un fichier .env ignoré par git, et .dockerignore qui exclut .env, mes notes personnelles et les journaux de l'image. Les tests et la CI utilisent des secrets factices.

Sur Azure

Chaque variable est un secret Container Apps, lu par l'API et la collecte par référence (secretref:). Je les ai créés depuis mon .env par un script qui n'affiche que leurs noms. Aucun secret dans l'image ni dans le dépôt.

Sur GitHub

Les trois identifiants de la connexion OpenID Connect en secrets du dépôt, et DEPLOY_ENABLED en variable. Le jeton d'envoi de l'interface n'y est pas : la CD le lit dans Azure à chaque fois.

À RETENIR Une mise à jour de l'image garde les secrets et les réglages.

La CD ne change que l'image (az containerapp update --image, az containerapp job update --image) : SOURCES_DESACTIVEES=document et les secrets restent en place d'un déploiement à l'autre.

CHAQUE MATIN

Le mail de bilan

Envoyé par le nœud report : statut de la nuit, chiffres par source, alertes, couverture famille et soirée de la semaine, coût Mistral. Le lundi, s'y ajoutent les recherches ratées et les propositions de l'agent. L'envoi SMTP fonctionne depuis Azure depuis la première collecte.
